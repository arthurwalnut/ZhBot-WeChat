# ZhBot v0.2.6

## 修改

- 抽取指令改为 `今日zxj`，帮助同步更新；`随机zxj` 不再抽取，按未识别指令提示。原每日额度、日期/换行文案、`我的zxj` 历史查询不变
- 回复的可见 @ 标签优先使用原生群昵称，其次微信昵称；补查非好友群成员缓存，不再把原生 wxid 当作缺失昵称的替代文本
- 原生提及目标仍使用原始成员 ID。名称读取按本次目标群执行，发送时重新读取，不使用跨群名称缓存
- 名称暂时不可用时，在原生发送前返回可重试失败，沿用 outbox 的有限重试；复用已保存的业务结果，不再次抽取或扣次数。发送结果不确定时继续保持不自动重发

本版没有修改 Wordle、表情库、管理后台、数据格式或固定 EXE。安装、启停、数据位置和完整调用关系沿用 [v0.2.5 交付说明](DELIVERY_v0.2.5.md)，现行指令见 [README](../README.md#群指令)。已有安装继续使用同一个 `ZhBot.exe`。

## 原因与来源

旧代码在 helper 返回空名称时拼接 `@wxid`。固定上游的名称查询只读取常规联系人缓存，遗漏非好友成员缓存。本轮实际只读检查中，一个已授权群可读到 10 名成员，但原接口只有 2 名有名称；补查后取得非好友成员名称，用户指定成员的实际群内名称与读取结果一致。涉及原生账号/群/消息编号的记录仅留在本机运行目录。

读取补充实现来自上游 helper 提交 `7302da4721ee87199d7828a134a3d7ac846799d1`，其原版限制为 4.2.0.11；本地另核验了当前 4.1.15.56 的具体缓存布局和实际名称。保留构建门槛、账号核对、成员 ID 对照、双读一致性检查，不扫描任意内存、不触发网络拉取。来源和完整许可见 [第三方声明](../THIRD_PARTY_NOTICES.md)。

生产 helper 继续固定为 `3e65e4bdaff438dc616f32d412175842fa138763`，两个 DLL 及校验值不变。未升级或降级微信，也未引入其他上游功能。

- 使用实际机器人进程只读运行新的名称补查与完整 @ 标签解析，结果与用户提供的具体成员/名称一致；这项检查没有发送消息
